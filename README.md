# 거북목 판별기 (turtle_neck)

웹캠 1개로 앉아 있는 사람의 자세를 실시간으로 보고, **목만 앞으로 빠진 거북목**을 정상 / 경고 / 위험으로 판정해서 서버로 보내는 프로그램입니다. 결과는 웹 페이지에서 표로 확인할 수 있고, 라즈베리파이에서도 동작하도록 가볍게 만들었습니다.

```
웹캠 → posture.py (판별) → posture_data.db (보관) → app.py (서버) → turtle_neck.db → 웹 페이지
```

## 파일 구성

| 파일 | 역할 |
|---|---|
| `posture.py` | 판별기. 웹캠으로 자세를 학습·판정하고 결과를 서버로 보냄 |
| `app.py` | 서버. 결과를 받아 DB에 저장하고 웹 페이지(`http://서버IP:5050`)로 보여 줌 |
| `config.json` | 판별기 설정 (서버 주소, 판정 기준, 카메라 설정 등) |
| `test_posture.py` | 카메라 없이 판정 계산과 서버 연동을 확인하는 테스트 |
| `forward.py` | (선택) 서버 DB의 데이터를 다른 웹 서버로 옮겨 보낼 때 사용 |
| `templates/index.html` | 결과 표 웹 페이지 |

실행하면 자동으로 생기는 파일은 `baseline.json`(학습 결과), `posture.log`(실행 기록), `posture_data.db`(판별기 쪽 전송 대기 DB), `turtle_neck.db`(서버 DB)입니다. 저장소에는 올리지 마세요.

## 필요 환경

| 항목 | 버전 | 이유 |
|---|---|---|
| Python | 3.9 ~ 3.12 (3.11 권장) | mediapipe 0.10.18이 이 범위만 지원 |
| mediapipe | **0.10.18** | 0.10.30 이상은 이 코드가 쓰는 `mp.solutions`가 없음. 0.10.20·0.10.21은 라즈베리파이용 설치 파일이 없음 |
| OpenCV, numpy | mediapipe와 함께 자동 설치 | `opencv-python`을 따로 설치하면 충돌할 수 있음 |
| flask | 제한 없음 | 서버(`app.py`)용 |

웹캠이 필요하고, 라즈베리파이는 64비트 OS여야 합니다.

## 실행

1. `config.json`의 `server_url`을 맞춥니다. 판별기와 서버를 같은 기기에서 돌리면 `"http://127.0.0.1:5050/api/record"`, 서버가 다른 컴퓨터면 그 컴퓨터의 IP를 적습니다.
2. 터미널 1에서 서버를 켭니다: `python app.py`
3. 터미널 2에서 판별기를 켭니다: `python posture.py`
4. 브라우저에서 `http://127.0.0.1:5050`(또는 서버 IP)을 열면 결과가 쌓입니다.

종료는 카메라 창에서 `q`, 다시 학습은 `c`입니다. **수정한 파일이 실제로 실행하는 폴더에 있는지** 꼭 확인하세요(예: Thonny에서 연 폴더와 터미널에서 실행하는 폴더가 다르면 수정 내용이 반영되지 않습니다).

## 카메라 설치

웹캠은 **모니터 위 가운데**에 두고, 화면에 얼굴과 양쪽 어깨(가슴 위쪽까지)가 나오게 합니다. 어깨가 보여야 몸통 움직임을 빼고 목만 판정할 수 있습니다. `config.json`의 `camera_tilt_deg`는 웹캠이 아래로 기울어진 각도로, 모니터 위에서 내려다보면 10~15, 노트북 화면 웹캠이면 0~5 정도로 대충 맞추면 됩니다. 카메라에는 한 사람만 나오게 하고, 역광(뒤에 창문)은 피하세요.

## 자세 학습 (처음 한 번, 관람객마다)

카메라 앞에 앉으면 자동으로 시작합니다. 화면 안내는 영어로 나옵니다.

1. **`1/2 SIT UP STRAIGHT 3, 2, 1`** → 바르게 앉아 3초 유지 (`HOLD STRAIGHT...`)
2. **`2/2 NOW TURTLE NECK! 3, 2, 1`** → 평소 나쁜 자세처럼 **몸통은 그대로 두고 머리만 앞으로** 빼서 3초 유지 (`HOLD IT...`)
   - 화면에 `head forward +O.Ocm`로 목이 앞으로 나온 거리가 실시간으로 보입니다. **2cm 이상**이면 충분합니다.
   - 대부분 한 번에 끝나고, 바른 자세 단계는 다시 하지 않습니다.
   - 오차가 너무 크면(목이 1.5cm도 안 움직였거나 많이 흔들림) `One more time ...`이 뜨고 2단계를 **딱 한 번만** 더 합니다.
   - 두 번째도 부족하면 더 반복하지 않고, 거북목은 기본값(목 앞 5cm, 아래 2cm)으로 학습해서 바로 판정을 시작합니다.
   - 학습 중 잠깐(3초 이내) 얼굴이 가려져도 처음부터 하지 않고, 측정만 멈췄다가 이어서 합니다.
3. 학습이 끝나면 실시간 판정이 시작됩니다. 화면 아래 막대가 점수, 흰 선 두 개가 경고·위험 기준입니다.
4. 자리를 5초 이상 비우면 다음 관람객을 위해 1단계부터 다시 학습합니다. 개인용으로 쓸 때는 `new_person_reset_sec`을 0으로 하면 학습 결과를 저장해 두고 계속 씁니다.

## 판별 원리

### 1. 귀의 3D 위치

Face Mesh(얼굴 468점) 중 표정이 바뀌어도 움직이지 않는 33점(콧등·눈 끝·광대·이마)을 MediaPipe 표준 얼굴 3D 모형에 맞춰(`solvePnP`) 머리의 3D 위치를 구하고, 그중 **귀** 위치를 씁니다. 코가 아니라 귀를 보기 때문에 키보드를 내려다보는 것처럼 고개만 숙이는 동작은 거의 영향이 없습니다.

### 2. 몸통 움직임 빼기 (핵심)

어깨(Pose)의 3D 위치도 구합니다. 어깨가 카메라에 가까워지면 넓게 보이는 것으로 앞뒤 거리를, 화면 속 높이로 위아래를 계산합니다.

고관절을 축으로 몸을 숙이면(척추 중립) 고관절-어깨-귀가 한 직선처럼 같이 돌아서, 귀는 어깨가 움직인 만큼의 `(몸통 + 목) / 몸통` 배(약 1.3배) 움직입니다. 그만큼을 빼면 **목만 앞으로 나온 거리(cm)** 가 남고, 이것이 거북목입니다.

- 어깨가 앞뒤로는 거의 안 움직이고 위로만 움직이면 어깨 으쓱으로 보고 무시합니다.
- 어깨가 멀어져 보일 때는 화면 속 높이도 같이 올라가야 "뒤로 기댐"으로 인정합니다. 높이가 그대로면 몸 비틀기로 보고 무시합니다.
- 몸통 길이·카메라 각도는 사람마다 달라서, 몸통이 많이 움직였을 때는 그 12%를 계산 오차로 보고 봐줍니다.

### 3. 개인 맞춤 점수

학습 때 거북목 자세에서 목이 몸통 기준으로 앞으로·아래로 몇 cm 움직였는지 기억하고, 지금 목의 움직임을 그 방향에 비춰 점수로 만듭니다. **바른 자세 = 0%, 학습한 거북목 = 100%** 이고, 화면과 전송 값은 0~100%로 제한합니다. 기본값으로 10% 이상이면 바로 경고, 20% 이상이 2.5초 이어지면 위험입니다.

### 4. 특수한 상황

| 상황 | 처리 |
|---|---|
| 팔을 듦 | Pose의 어깨 점이 팔을 따라 올라가서 못 믿음 → 팔을 들기 직전 어깨를 10초간 기억해서 사용 |
| 손으로 얼굴을 잠깐 가림 | 몸은 보이면 3초 동안 마지막 판정 유지 |
| 어깨가 화면 밖으로 나감 | 몸통 움직임을 뺄 수 없어서 판정하지 않음 (`MOVE BACK - show both shoulders`) |
| 사람이 떠남 | 1초 안에 정상으로, 5초 지나면 학습 초기화 |

### 5. 한 사람만 따라가기

처음 잡은 사람(가장 크게 보이는 얼굴)만 계속 따라갑니다. 얼굴은 3명까지 찾되, 바로 전 위치에서 가장 가까운 얼굴만 같은 사람으로 봅니다. 어깨는 그 사람 주변만 잘라서 계산하므로 옆이나 뒤에 다른 사람이 들어와도 그 사람의 어깨를 잡지 않습니다. 5초 넘게 안 보이면 다음 사람을 새로 잡고 새로 학습합니다.

### 6. 떨림과 반응 속도

귀와 어깨 측정값을 **똑같은 방식으로** 부드럽게 합니다. 움직일 때는 0.25초(`smooth_sec`), 가만히 있을 때는 0.6초로 더 부드럽게 해서 흔들림을 줄이고, 점수는 최근 3번의 가운데 값(한 번 튀는 값 무시)에 One Euro 필터를 겁니다. 둘이 똑같이 늦어져야 빨리 움직여도 서로 어긋나지 않습니다. 얼굴(초당 30번)과 어깨(초당 5번)는 계산 속도가 달라서, 판정할 때는 **같은 화면에서 나온 얼굴과 어깨를 짝지어** 씁니다. 이렇게 하지 않으면 빨리 숙일 때 귀만 먼저 움직인 것처럼 보여 순간적으로 오판합니다.

## 쓰레드 구조 (부하 줄이기)

| 쓰레드 | 하는 일 | 속도 |
|---|---|---|
| 카메라 | 웹캠 읽기. 항상 가장 최근 화면 하나만 보관 | 최대 `camera_fps` (30) |
| 얼굴 | Face Mesh 계산 | `analysis_fps` (30) |
| 어깨 | Pose 계산 (가장 무거움) | `pose_fps` (5) |
| 메인 | 화면 표시 + 판정 (계산량 아주 적음) | 화면은 카메라 속도, 판정은 어깨 결과마다 |

MediaPipe는 계산하는 동안 파이썬 잠금(GIL)을 풀어서, 얼굴과 어깨 계산이 서로 다른 CPU 코어에서 동시에 돕니다. 정해진 횟수만 계산하고 남는 시간은 쉬기 때문에, 같은 기기에서 도는 서버도 여유 있게 응답합니다. 화면 오른쪽 아래에 `cam / screen / face / pose` 초당 처리 횟수가 표시되고, 로그에도 10초마다 남습니다.

웹캠 60fps는 웹캠이 지원해야 하고(대부분 MJPG 방식에서만), 조명이 밝아야 나옵니다. 실행 5초 뒤 로그의 `카메라 실제 속도`로 확인하세요.

## 설정 (`config.json`)

| 키 | 설명 | 기본값 |
|---|---|---|
| `server_url` | 결과를 보낼 서버 주소 | 노트북 IP → 같은 기기면 `127.0.0.1`로 |
| `user_id` | 사용자 이름 | `user1` |
| `calib_sec` | 학습 때 자세별 측정 시간(초) | 3 |
| `warning_pct` | 경고 기준 점수(%). 실제로 깜빡임이 심하면 15~20으로 | 10 |
| `danger_pct` | 위험 기준 점수(%) | 20 |
| `danger_after_sec` | 위험 기준을 이 시간 넘어야 위험 | 2.5 |
| `hysteresis_pct` | 경고에 들어간 뒤 해제 기준을 이만큼 낮춤 (깜빡임 방지) | 3 |
| `smooth_sec` | 움직일 때 귀·어깨를 부드럽게 하는 시간(초). 가만히 있을 때는 0.6초 | 0.25 |
| `shoulder_tilt_deg` | 어깨 틀어짐 기준(°) | 5 |
| `save_interval` | 서버 전송 주기(초). 상태가 바뀌면 바로 전송 | 3 |
| `show_window` | 카메라 창 표시 (모니터 없으면 자동으로 끔) | true |
| `mirror` | 화면을 거울처럼 좌우 반전 | true |
| `model_complexity` | Pose 모델. 1: 정확 / 0: 가벼움(라즈베리파이) | 1 |
| `analysis_fps` / `pose_fps` | 얼굴 / 어깨 계산 횟수(초당) | 30 / 5 |
| `camera_fps`, `camera_width`, `camera_height`, `camera_fourcc` | 웹캠 요청 설정 | 30, 640, 480, MJPG |
| `camera_fov_deg` | 웹캠 가로 화각(°) | 65 |
| `camera_tilt_deg` | 웹캠이 아래로 기울어진 각도(°) | 10 |
| `use_shoulders` | 어깨 사용 여부. false면 몸통 보정 없이 판정 | true |
| `new_person_reset_sec` | 따라가던 사람이 이 시간 안 보이면 다음 사람을 잡고 다시 학습. 0이면 학습 결과 저장·유지 | 5 |

라즈베리파이 추천 설정은 `"analysis_fps": 15`, `"pose_fps": 5`, `"model_complexity": 0`입니다. 설정을 바꾸면 프로그램을 다시 켜야 반영됩니다.

## 카메라 창 글자 뜻

| 글자 | 뜻 |
|---|---|
| `NO PERSON` | 사람이 안 보임 |
| `FACE NOT FOUND` | 얼굴 인식 안 됨 → 정면 보기, 조명 확인 |
| `TURN TO CAMERA` | 고개를 35도 이상 돌림 |
| `MOVE BACK - show both shoulders` | 어깨가 화면 밖 → 뒤로 물러나거나 카메라 각도 조절 |
| `face hidden - keeping last result` | 얼굴이 가려짐 → 3초 동안 마지막 판정 유지 |
| `1/2 ...`, `2/2 ...` | 자세 학습 중 |
| `NORMAL` (초록) / `WARNING` (주황) / `DANGER` (빨강) | 정상 / 경고 / 위험 |

화면의 하늘색 점은 코·눈 끝·턱, 흰 선은 어깨·팔, 노란 선은 귀(추정)에서 어깨 가운데까지 이은 선입니다. 거북목이면 노란 선이 앞으로 기울어집니다.

## 가상 시뮬레이션 결과

모니터 위 웹캠과 앉은 사람의 3D 모형으로 MediaPipe 결과를 흉내 내어(측정 흔들림, 사람마다 다른 얼굴 크기 포함) 이전 버전과 비교했습니다. 점수는 0% = 바른 자세, 100% = 학습한 거북목입니다.

| 상황 | 이전 | 현재 |
|---|---|---|
| 거북목 / 가벼운 거북목 | 102% / 55% | 102% / 51% |
| 거북목 + 손 듦 | 불안정 | 102% |
| 고관절로 숙이기 15° / 25° | 206% / 494% | 1% / 1% |
| 숙인 상태 + 거북목 | 549% | 63% |
| 뒤로 기댄 채 거북목 | 26% | 66% |
| 키보드 내려다보기 | 52% | 0% |
| 의자째 다가가기 / 어깨 으쓱 | 75% / 0% | 0% / 1% |
| 몸통 20° / 30° 비틀기 | 40% / 114% | 0% / 0% |

몸통 길이(40~60cm), 카메라 기울기(0~20°), 화각, 앉은 거리가 달라도 고관절 숙이기는 0~2%였습니다. 가만히 앉아 있을 때 경고가 깜빡인 시간은 0%, 거북목을 하면 약 0.2초 만에 경고가 떴습니다. 숙인 상태에서 거북목을 하면 계산 오차를 봐주는 만큼 점수가 조금 낮게(44~83%) 나와서, 경고는 확실히 뜨지만 위험까지는 안 갈 수 있습니다.

시뮬레이션은 코드가 의도대로 동작하는지 확인한 것이라, 실제 정확도는 실제 웹캠으로 확인해야 합니다. 로그의 `목 앞으로 Ocm, 몸통 숙임 O°` 값으로 오판 원인을 볼 수 있습니다.

## 문제 해결

| 증상 / 메시지 | 원인과 해결 |
|---|---|
| 로그에 `기본값으로 학습` | 거북목 자세를 두 번 다 제대로 못 잼. 판정은 되지만 개인 맞춤이 아니므로, 필요하면 `c` 키로 다시 학습 (화면의 `head forward`가 2cm 이상 되게) |
| `전송 실패 ... timed out` | `server_url`의 IP가 틀렸거나 다른 네트워크. 같은 기기면 `127.0.0.1` |
| `전송 실패 ... Connection refused` | 서버(`app.py`)가 꺼져 있음 |
| `전송 실패, DB에 보관 중 N개` | 데이터는 `posture_data.db`에 안전하게 보관 중. 연결되면 자동 전송 |
| 수정했는데 그대로임 | 수정한 파일과 실행하는 폴더가 다름. `grep server_url config.json`으로 확인 |
| `카메라 연결 실패` | 웹캠 연결, 다른 프로그램(줌, 브라우저 탭) 사용 여부, 카메라 권한 확인 |
| 점수가 이상하게 튐 | 카메라에 다른 사람이 같이 잡힘. 한 사람만 나오게 |
| `has no attribute 'solutions'` | mediapipe가 너무 최신. `pip install mediapipe==0.10.18` |
| `config.json 형식 오류: N번째 줄` | 그 줄의 쉼표·따옴표 확인 (한글 따옴표, 끝 쉼표, `True` 대문자 등) |

## 최근 변경 내역

### 실제 사용 상황 대응

- 자세 학습 반복 최소화: 거북목 측정은 오차가 클 때만 한 번 더(최대 2번), 그 뒤에는 기본값으로 학습하고 바로 판정

- 어깨·팔 선 깜빡임 수정: 화면에는 항상 최신 어깨를 그림. 다리·얼굴 점 대신 어깨·팔과 귀-어깨 선만 표시
- 한 사람만 따라가기: 판정 중 다른 사람이 들어와도 처음 사람만 판정, 어깨도 그 사람 주변만 계산
- 경고·위험 기준 10/20으로 되돌리고, 그에 맞게 흔들림 처리 강화 (가만히 있을 때 더 부드럽게, 튀는 값 걸러내기, 바른 자세가 0%에 오도록 학습 방식 수정)
- 팔을 내리면서 숙이는 순간, 어깨 으쓱, 몸 비틀기, 뒤로 기대기에서 순간적으로 경고가 뜨던 문제 수정

### 자세 학습 무한 반복 수정

- 거북목 측정이 부족하면 최대 3번까지만 다시 요청하고, 그래도 안 되면 1단계부터 다시 하도록 변경 (무한 반복 제거)
- 학습 기준을 라즈베리파이 환경(초당 5번 측정, 큰 흔들림)에 맞게 완화: 목이 1.5cm 이상 움직이고 흔들림의 2배 이상이면 성공
- 2단계에서 목이 앞으로 나온 거리(`head forward`)를 실시간 표시, 실패 이유를 화면과 로그에 표시
- 학습 중 잠깐 얼굴이 가려져도 처음부터 하지 않고 이어서 측정
- 어깨 너비 계산에서 흔들림이 큰 MediaPipe 앞뒤 깊이(z)를 제외하고, 몸 비틀기는 어깨 높이 변화로 구분

### 판별 구조 개선

- 고관절로 숙이기를 거북목으로 오판하던 문제 해결: 귀 3D 위치에서 몸통 움직임을 빼고 목만 움직인 거리로 판정
- 손을 들면 판정이 안 되던 문제 해결: 팔을 들기 직전 어깨를 기억해서 사용
- 점수 100% 초과 제한, 얼굴 모형 6점 → 33점으로 안정화
- 얼굴·어깨 결과를 같은 화면끼리 짝지어 빠른 움직임에서의 순간 오판 제거
- 경고·위험 기준 10/20 → 30/60 (새 점수 체계에 맞춤)

### 성능·전송

- 카메라·얼굴·어깨·메인 4개 쓰레드로 분리, 웹캠 60fps 요청
- 전송 대기 시간 1초 → 5초, 프록시 설정 무시 (라즈베리파이 전송 실패 해결)
- 못 보낸 데이터는 `posture_data.db`에 보관했다가 자동 재전송
